# Prisma 首场素材生成方案

首轮交付《转生了的大圣女》序章家庭会议的 8 个可用文件。用现有 Scenario 的 `1:2` 场验证从剧本提取需求、写提示词、生成文件、审阅和导出的完整链路。用现有 `cues.json` 挂载，检查素材在正确时机出现。首轮的数量、画面方向和模型是试作选型，需用候选质量验证。

## 首批素材

| 素材 | 数量 | 剧本依据与演出 |
| --- | ---: | --- |
| 路特家会议室 | 1 | `1:2/01–04` 写明在家中最大房间开家庭会议。`/01` 显示背景。时段、桌椅和采光由美术定稿。 |
| 姐姐的基准立绘和表情 | 3 | `/02` 显示说话姿态的基准立绘，`/08` 切为绷眉张口反驳，`/17` 切为垂眼松眉劝说。两种表情均引用同一张已选底图。 |
| 姐姐的日语配音 | 2 | `/08` 反驳和 `/17` 劝说各生成一个文件。用同一音色试演两种语气。 |
| 家庭争执 BGM | 1 | `/01` 起，先做约 40 秒的纯器乐。选定候选后裁出循环段，与对白合听。 |
| 磨剑音效 | 1 | `/10` 播放一次。短促的室内金属摩擦声，留自然衰减。 |

背景交付 1280 × 720 PNG，立绘交付透明 PNG，三张使用同一画布和站位。音频交付 WAV 或 OGG，保留模型原文件。脸部差分的局部图层留在制作目录，由本地工序和基准图合成，再把整张立绘交给现有导出器。首轮通过后可用「树根救雏鸟」试做 CG，用已选角色图和地点图验证跨素材的外观一致性。[序章试作清单](media-checklist.md) · [表情差分规格](media-variants.md)

## Scenario 到提示词

1. **读一场戏。** 用现有 `parse_scenario()` 取场次、展示文本和说话人。随同该场提供项目画风、声线方向、角色别名、已经选定的素材和词表。提取模型返回结构化需求，每项带剧情证据、使用位置和建议 Tag。把原文事实和演出提议分别列在卡片中。例如「家中最大的房间」来自原文，午后采光属于待审提议。称呼歧义交给作者确认。已有素材满足同一个角色状态或同地点镜头时，增加使用位置即可。
2. **审核每个生成请求。** Prisma 按媒介把需求、项目风格、指定版本的参考资产和人工补充内容组装成提示词。作者可同时看到原文、Tag、参考图、实际提交的参数和待补设定。批准这张提示词卡后才提交生成。模型只收到本次生成相关的描述、台词和参考文件。
3. **保存和审阅候选。** 每项先提交一个候选，按需补第二个。后台保存原始文件、处理后的文件、模型和参数、提示词版本、参考版本及服务商任务 ID（如果有）。界面提供看图、听音、差分叠图和选定按钮。打回候选后回到该项提示词，可改单项再提交。其他已通过、未引用变更内容的素材可继续使用。
4. **导出一轮。** 从本次选定的候选和使用位置生成 `cues.json`。场次和展示条目沿用现有编号，另保存 Scenario 内容指纹及该项引用的文本。Scenario 有改动时，对照当时的文本复核位置，再导出有变动的绑定。更换立绘底图时，标记引用旧底图的差分待复核。修改一句台词时，只重做该句语音和受其内容影响的演出。

| 记录 | 用途 |
| --- | --- |
| 素材需求 | 保存素材 ID、类别、角色或地点、Tag、剧情证据和使用位置。同一套素材可以关联多场。 |
| 提示词版本 | 保存本次精确请求，包括提示词、模型参数及引用的定稿版本，记录是否已审核。 |
| 候选 | 指向生成它的提示词版本，保存任务状态和文件。一个需求可以有多个候选，选定其中一个供导出。 |

**会议室提示词样例** · 日式轻小说插画风的中世纪骑士家庭会议室。16:9，视点在门口，成人平视，长木桌和座椅向画面纵深延伸。浅石墙、木梁，左侧高窗提供柔和光线。前景留出放立绘的空间，下沿留给对白框。清晰线稿、克制色彩，空室画面，无人物、无文字。机位、材质和采光作为待审设计填入项目设定。

**姐姐表情差分样例** · 参考已选基准立绘，固定头部轮廓、发际线、衣着、机位、光向和画布锚点。局部改眉、眼、嘴。`/08` 的内眉下压、双眼睁大、张口反驳，`/17` 的眉眼放松、视线微垂、嘴微张。两条分别生成。选中后将编辑区域对齐并贴回底图，检查脸部边缘及五官位置。

**配音请求样例** · `/17` 保留中文 Scenario 的文本编号，另存校对后的日语台词。用姐姐定稿的日语音色合成，演出方向为「放低音量，语速稍缓，像在安慰妹妹」。用所选模型支持的语速、语调或表演标签实现，试听时核对读音、停顿和音色。

## 模型与交付工序

| 任务 | 首选模型 | 调用与后处理 |
| --- | --- | --- |
| 剧本提取与提示词草拟 | Gemini 3.8 Flash | 用结构化输出返回需求草稿。后端再校验资产类别、Tag、角色与文本引用，编辑后的提示词单独留版本。[模型文档](https://aistudio.google.com/docs/models/gemini-3.8-flash) · [结构化输出](https://ai.google.dev/gemini-api/docs/structured-output) |
| 背景、立绘、表情与 CG | FLUX.2 [pro] | 先生成背景与角色底图，后续编辑传入已选参考图。立绘的抠图、透明通道、画布对齐和局部贴图在本地处理。底图和差分叠放审阅，确认发际、五官和服装轮廓稳定。[模型文档](https://bfl.ai/models/flux-2) |
| 角色语音 | 本地 VOICEVOX | 逐句输入日语台词，固定音色 ID，通过语速、音高和语调调节表演。逐句保存 WAV，核对读音和音色后再挂载。候选记录实际音色及其署名。[VOICEVOX Core 指南](https://github.com/VOICEVOX/voicevox_core/blob/main/docs/guide/user/usage.md) |
| BGM | Eleven Music `music_v2_5` | 提示词描述克制的室内弦乐、稀疏钢琴和对白空间，设置目标时长及 `force_instrumental`。本地裁循环点，听接缝和对白下的响度。[音乐 API](https://elevenlabs.io/docs/api-reference/music/compose) |
| 音效 | ElevenLabs `eleven_text_to_sound_v3` | 按「物体、材质、动作、距离」提交。磨剑这次生成约 2 秒，`loop=false`，试听起音与衰减。[音效 API](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert) |

## 开发顺序与验收

1. **先把文件做出来。** 用这一场产出需求 JSON 和可提交的提示词，经审阅后从已有模型入口生成。把候选文件、提示词和参数登记到同一份清单。先拿下背景、基准立绘和两句语音，再完成差分、BGM 和音效。以每项一次生成做首轮预算，听看后再决定补哪些候选。
2. **存好项目状态，再接自动调用。** 沿用现有 Python 后端与 Web UI。加一个「素材」页，能从当前场次提取需求、改提示词、提交单项生成、比较和选定候选。初版把元数据存在本地 SQLite，文件放项目目录。重启后可继续查看进度。把服务商请求和落盘封装在各媒介的调用模块中，调用失败只重试对应项。遇到超时且状态不明时先查原任务，避免重复生成和计费。
3. **拿真实文件验收。** 首轮结束时能打开 8 个交付文件，能从任一文件追溯到剧本位置、提示词和模型参数。实测 `/08` 和 `/17` 用同一音色、表情切换时身体与画布保持对齐、BGM 循环听不出跳点、`/10` 有一次磨剑声。先用已批准的背景构建一次，再加入配音构建一次，核对背景引用一致。用现有 Ren’Py 导出验证实际挂载，浏览器审阅页也应能独立预览候选。
