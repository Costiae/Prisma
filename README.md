# Prisma · 视觉小说制作管线

当前版本提供本地 Web UI 和 Python 命令行。`draft` 把原始文本整理成可校对的 Scenario，`build` 把校对后的剧本和指定的演出、素材写成原生 Ren’Py `.rpy`。可以先生成纯文字工程，再在工作台制作背景、立绘和 CG，或导入已有素材。

## 本地 Web UI

从仓库根目录启动。需要 Python 3.11 或以上版本，仅使用标准库。

```powershell
python webui.py
```

打开 [本地工作台](http://127.0.0.1:8765/#projects)，在「项目库」新建或打开项目。点击路线图中的节点进入工作台。顶部用同款路线图显示可点击的直接上下游，中间可调参并查看成果，底部可重试或通过。通过后版本会自动传给所有直接下游。在「工程导出」检查缺项、选择字体并下载 Ren’Py ZIP，再解压到 SDK 中打开。

「项目配置」按文本、图像和训练用途分别设置模型。文本任务默认继承项目全局 LLM；需要单独模型或提示词时，在该任务的 Override 中打开覆盖。图像生成的本地底模与在线模型、LoRA 训练底模分别配置。

当前文本、演出绑定和素材会自动写入项目历史，可以手动写入或撤回。也可以分别下载 Scenario 和演出 JSON。Scenario 的每条文本都有稳定 ID，演出绑定随 ID 移动。导入旧的编号绑定后，可以点「固定演出位置」按当前编号转换，转换前请核对位置。端口冲突时可加 `--port 8766`。WebUI 支持逐个登记不超过 45 MiB 的上传素材，较大的本机文件可用命令行构建。

## 从零开始与 MCP

没有模型时，可以配置在线图像 API 直接生成，也可以用本地工具箱安装底模、导入自己的参考图并训练 LoRA。WebUI 与 MCP 共用一个服务和任务目录，Scenario、素材提示词、安装、训练、出图、复跑、产物读取和 Ren’Py 导出都可通过 MCP 操作。直接连接 `http://127.0.0.1:8765/mcp`，或为 stdio 客户端配置 `mcp_stdio.py`。[从零开始、MCP 配置与可复跑示例](docs/reproducible-workflow.md)

### 图像生成

在左侧选择「图像生成」。可以粘贴提示词、载入样例，或把当前场景的几句文本带入提示词，再补充人物外观、动作和构图。生成后可预览、下载，或点「加入素材」，再到「演出」中用作背景或立绘。候选图和任务记录会留在磁盘。安装底模、管理数据集和训练 LoRA 在「模型与训练」。

| 模式 | 使用方法 |
| --- | --- |
| 本地模型 | Windows x64 使用 Vulkan 推理和 CUDA 训练；Apple Silicon Mac 可用 MPS 训练 SD 1.x/SDXL LoRA，也可用 Apple MLX 在 512 分辨率训练 Iris-3B 或动漫专用 Anima Base LoRA，并通过 MLX 本地生成。 |
| 在线模型 | 在「API Provider」选择 OpenAI 或 Anthropic 兼容格式，填写地址和 Key。使用 Fetch Models 获取模型及 metadata，也可手动声明模型。在页面下方保存文本、图像和音频默认模型。流程节点可继承默认模型或指定目录中的模型，并调整生成参数。 |

本地模式会查找 `E:\LLM\prisma-media`（可用 `PRISMA_MEDIA_HOME` 指定已有安装的位置）和本项目以往的 R1/R2/R3 权重。选择「套用 R2 / R3 对照配置」可按相同 Seed 比较 R2、R3 各自 200 步、0.35 权重的结果。两支权重相互独立，可以分别继续使用。

LoRA 工具箱可自动拉取约 2.13 GB 的 Anything V3 或 6.94 GB 的 Animagine XL 4.0 Opt（动漫专用 SDXL checkpoint），以及训练用的 Python 3.10.20、PyTorch、sd-scripts 和对应的 CLIP 分词文件。Windows 使用 CUDA 12.4 与 8-bit AdamW；Apple Silicon 使用 PyTorch 2.8 MPS 与标准 AdamW。Iris-3B 与 Anima 使用独立的 Apple MLX 环境，固定 Python 3.13 和 MFlux 提交 `02b92461ec246ec44f5149b5dc3f69817a263a67`。Iris 下载约 20 GB；Anima Base 下载动漫底模、VAE 和分词器，合计约 5.7 GB。Anima Base 固定到官方仓库提交 `457fbf842cb86e96af72c65bdd13e3f1c448de84`，训练输出为 ComfyUI 兼容 LoRA。Anima 模型与衍生权重仅限非商业用途。训练任务会记录模型提交、权重校验值、依赖版本和数据集清单。首次安装需联网并预留下载和解压空间。工具箱还可以：

1. 从 `Reference/Img`、R2/R3 原训练集或上传的图片选择训练素材，编辑每张图的标注并保存为独立数据集。
2. 选择 SD 1.x、SDXL、Iris-3B Base 或 Anima Base，设置步数、保存间隔、Rank、学习率和 Seed，训练独立分支。Iris 和 Anima 使用 512 分辨率、batch size 1、梯度检查点和 2 GB MLX 缓存；步数会按数据集大小取整为完整轮次。Anima 默认 Rank 16、25 个数据轮次，并使用其全部 28 层的注意力、MLP 与 AdaLN 模块。可查看日志或取消本地任务。训练完成后，可下载预览图与 checkpoint；Apple Silicon 可直接用 MLX 生成 Anima Base 与 LoRA 对照图。
3. 导入兼容 SD 1.x 的 `.safetensors` LoRA。大于 45 MiB 的文件可直接复制到 `build/prisma-images/loras`，再刷新环境。

新下载、数据集、任务日志、出图和训练权重默认写在 `build/prisma-images/`；可通过 `--image-workspace` 自定义位置。工具箱不会改动原参考图或既有 R2/R3 训练结果。

换设备时，可从「模型与训练」导出所选 LoRA，也可用 `lora_export.py` 一次导出多个检查点。ZIP 解压后可以直接作为图像工作目录使用，底模从目标设备的模型目录加载。 [LoRA 迁移说明](docs/lora-transfer.md)

「项目」可保存和恢复原文、Scenario、演出绑定和素材版本。「资源目录」用同一个 SQLite 索引管理这些记录，以及提示词、图片、音频、字体、模型、训练任务和导出。 [资源目录与 MCP 用法](docs/resource-library.md)

## 运行基础流水线

构建需要 Python 3.11 或以上版本，仅使用标准库。从仓库根目录运行，先把 `path/to/novel.txt` 换成实际文件路径。中文预览可用 `--font` 指定覆盖所需字符的字体，示例使用 Windows 的微软雅黑。

```powershell
python prisma.py draft 'path/to/novel.txt' build/scenario.json
# 在 WebUI 的「场景与台词」中校对说话人，再构建。
python prisma.py build build/scenario.json build/novel --font C:/Windows/Fonts/msyh.ttc
```

`draft` 保留原文顺序，识别 `#` 章节标题，把 `---`、`◇◇◇` 和缩进的数字分节转换为 JSON 场景。整段用 `「」` 包住的文字在未指定说话人时标记为 `speaker: "？"`，须在构建前校对。`--speakers` 接收原文行号到角色名的 JSON 映射，值为 `null` 时原文引号会作为旁白保留。带卷首简介的小说可以用 `--from-heading '# 章节名'` 指定起点，说话人仍按原文行号填写。

`build` 检查说话人并生成 `game/script.rpy`。省略 `--cues` 就生成纯文字版。要挂载已有素材，可按下例创建 `cues.json`，填入实际文件路径，再用 `--cues cues.json` 构建。`1:1` 指第一章第一场，`1` 和 `4` 指该场的第一条和第四条展示文本。在下文的车站 Scenario 中，第四条是周明的第一句对白。每条列表里的动作在对应文本显示前依次执行。相对素材路径以 JSON 文件所在目录为基准，输出工程只复制用到的文件。

```json
{
  "1:1": {
    "1": [{ "background": "assets/station.png" }],
    "4": [
      { "show": { "actor": "周明", "file": "assets/zhouming.png" } },
      { "voice": "assets/zhouming-line-1.wav" }
    ]
  }
}
```

现有动作包括 `background`、`show`、`hide`、`music`、`sound` 和 `voice`。`music: null` 停止音乐，每句有署名的对白最多挂一条 `voice`。换场只推进剧情顺序，画面和音乐延续到相应的演出指令。每条文本都有稳定 ID。演出 JSON 可用 `{"by_line_id":{"line-1":[{"voice":"assets/zhouming-line-1.wav"}]}}` 引用稿件中的 `line-1`。旧的编号绑定可在 WebUI 固定到 ID。重复运行时请为 `draft` 选用新的输出文件，为 `build` 选用新的输出目录。

预览需要单独安装 Ren’Py SDK。在 Launcher 里将项目目录设为 `build` 的绝对路径，选择生成的 `novel` 工程。Windows 也可从 SDK 目录运行语法检查，将下例的路径替换为实际工程目录。

```powershell
.\lib\py3-windows-x86_64\python.exe renpy.py 'C:\path\to\Prisma\build\novel' lint --error-code
```

目前已用车站样例、Bukiyou 小说片段和《转生了的大圣女》的序章验证 Scenario 和 `.rpy` 生成。Bukiyou 片段也验证了素材挂载。Ren’Py 的 lint 和实际播放仍待验证。

## Scenario 格式

Scenario v1 是一个 JSON 对象。章节、场景和文本的排列顺序由各自的数组决定。`speaker: null` 表示旁白，`viewpoint`（叙述视角）和 `direction`（动作或语气）是可选的编辑信息。`source` 保存可选的原文或旧版剧本行号，`kind` 分别为 `raw` 和 `legacy`。在 WebUI 可按章节、场景和台词编辑和重排，演出绑定随文本 ID 保留。

```json
{
  "version": 1,
  "chapters": [{
    "id": "1",
    "title": "第一章　末班车",
    "scenes": [{
      "id": "1:1",
      "lines": [
        {"id": "line-1", "speaker": null, "text": "雨敲着玻璃。", "source": {"kind": "raw", "line": 3}},
        {"id": "line-2", "speaker": "林岚", "text": "你还知道回来。", "direction": "压着火"}
      ]
    }]
  }]
}
```

旧版 Markdown 可以直接导入 WebUI 或传给构建命令。Prisma 会保留已有的台词 ID，随后可下载 JSON 或把它保存在项目新版本里。

## 本地参考

`Reference/` 存放本地参考游戏、小说和素材。`examples/` 可放待试跑的本机 TXT 原文。这两处本机数据由 Git 忽略。

Bukiyou 的第一话可以对照小说与 Ren’Py 脚本。罗伊先说话，稍后才显示立绘，这段已用于验证配音和立绘可以挂在不同位置。游戏还用 `layeredimage` 将小春的底图与同画布的脸部差分叠加，可作为后续立绘差分的参考。

## 开发路线图

### 已接通的制作流程

原文 → Scenario JSON → 场景提示词 → 图像候选 → 项目素材 → 演出绑定 → Ren’Py 预览与导出。校对过的 Scenario 也可直接导出纯文字工程，或先导入现成素材再挂载。

| 环节 | 当前能力 |
| --- | --- |
| 项目与资源目录 | SQLite 以 `project_id` 记录资源归属。打开项目后可查看该项目的资源和生成任务，也可切换到共享库。工具、底模和选定的 LoRA 或数据集可共享。项目版本保存原文、Scenario、演出绑定、素材引用和字体。[资源目录与迁移](docs/resource-library.md) |
| Scenario | 原文可直接生成 Scenario JSON，旧版 Markdown 可导入。WebUI 按章节、场景和台词阅读、校对与重排，台词 ID 用于下游引用。 |
| 提示词与图像生成 | `scenario_asset_prompt` 用选中的场景、附近台词和作者补充说明拟定背景、立绘或 CG 的提示词。在线 API 和本地安装是独立入口。任务记录实际使用的提示词、模型和生成参数，选中的图可以加入项目素材。[安装、生成与复跑](docs/reproducible-workflow.md) |
| LoRA 训练与迁移 | 本地任务登记底模、数据集、训练参数、工具版本和检查点。迁移可导出所选 LoRA、数据集和任务记录，底模在目标设备单独安装或复用。[LoRA 路径与迁移](docs/lora-transfer.md) |
| 素材与脚本工作台 | 图片和音频可导入并预览。在 WebUI「演出」中点选 Ren’Py 预览里的台词，可插入或替换背景、立绘、BGM、音效和配音等动作。`script_preview` 与 `script_bind` 提供相同的 MCP 操作，绑定保存在 `cues` 中，按稳定台词 ID 定位。ZIP 导出使用同一个脚本生成器。 |

### 梗概与资产分支

目前直接读取原文的是 Scenario 草稿器。以下三种梗概尚未实现自动生成，计划统一读取校对后的 Scenario JSON，并保留所用 Scenario 版本与台词 ID。核对剧情依据时，可由 `source` 行号回查项目保存的原文。梗概的阅读和审阅放在 WebUI。

| 待接入的产物 | 输入与用途 |
| --- | --- |
| 章节梗概 | 读取该章的场景与台词，整理事件和转折，供作者逐章审阅。 |
| 内容总览 | 汇总从完整 Scenario 提取的章节梗概和场景事实，整理时间、地点、世界观和作品基调，供背景和音乐分支使用。 |
| 角色概览 | 从相关行动、对白、称谓和关系找出角色线索，结合作者提供的人物与人声参考，定稿角色外观和声音。 |

制作需求引用相关梗概和具体场景，记录使用位置、剧情依据和 Tag。表情与音乐的 Tag 使用各自的词表。提示词按媒介选取所需的文本、参考素材和人工补充说明，画风参考可在共享库复用。

| 待接入的资产能力 | 依赖与交付 |
| --- | --- |
| CharaDesign 与立绘差分 | 先确认角色设计及基准立绘，记录母版版本、画布和站位。用同一母版生成表情差分，局部重绘后合成，并叠图检查五官、发际线和身体位置。 |
| CG 一致性 | CG 候选引用已定稿的角色母版和相应场景，审阅时核对人物外观、服饰和构图。 |
| 日语配音 | 先定稿每个角色的音色和表演方向，再按校对后的日语台词生成。语音记录引用台词 ID 与声音基准版本。 |
| BGM 与音效 | 用内容总览、该场的情绪或动作，以及作者提供的音乐参考组织生成请求。成品可沿用现有音频挂载入口。 |

当前由作者选图、试听和手动挂载。项目按节点记录当前结果与所用输入，后续资产分支可据此复用已选版本。需要新候选时，可以在原节点改参数或再次生成。已选背景可先挂载，后补配音时沿用背景绑定。

素材制作规格和样本项目示例见[通用素材与 Prompt](docs/media-prompt-guide.md)、[《大圣女》全局素材清单](docs/media-checklist.md)和[差分规格](docs/media-variants.md)。

### Token 用量与生成成本

Scenario 草拟、基础资产提示词、演出绑定与 Ren’Py 编译均为本地规则处理。场景提示词入口接收整份 Scenario，返回目标附近的几句台词供参考。`scenario_inspect` 同时返回标准 JSON 和展开的场景。在线出图任务保存参数和产物，尚未保留服务返回的 `usage`。[OpenAI 图像生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)

用 96 场、1,536 行的合成剧本对照请求体积。现有提示词请求的紧凑 UTF-8 JSON 为 257,434 字节，将整份剧本换成 64 字符的 Scenario ID 后为 158 字节。这个对照衡量序列化体积，实际 Token 和费用按客户端与服务商分别实测。

| 优化点 | 拟采用的做法 |
| --- | --- |
| 跨工具按 ID 复用 | 在现有后端增加按 `scenario_id`、场景 ID 和台词 ID 取用的入口。WebUI 和 MCP 保存一次后传 ID，按章节或场景读取正文。保留完整 JSON 的导入和读取，也允许直接使用编辑中的内容。场景原句在 WebUI 中供作者核对，提交图像任务时由作者决定是否带上相关摘录。 |
| 分场提取、跨分支复用 | 把已校对场景的人物、地点、事件和视觉线索提取为带证据台词 ID 的结构化记录。章节梗概与内容总览由场景记录逐级汇总，角色概览按角色和别名取相关证据。各资产分支只取所需的事实、定稿设定和少量原句。为各步骤设输入与输出上限，遇到跨章伏笔或身份歧义时按证据追加上下文。 |
| 按实际依赖增量重算 | 复用现有 SQLite 资源关系与落盘记录。以项目、操作、实际输入片段和参考版本、模板及输出结构版本、模型和有效参数识别可复用结果。场景记录保留来源版本用于追溯。改一句台词只重算受影响的场景记录及其下游。主动出新候选可沿用提示词，重复提交同一操作则复用已有任务。超时后先查任务和可取得的服务商状态，费用未知时保留待确认记录。 |
| 用量记录和预算 | 按外部请求保存项目、阶段、任务 ID、服务商和模型版本、计费单位、用量与价格依据。文本记录输入、缓存命中、输出和服务商报告的推理用量，媒体按实际计费单位记录。提交前按任务和项目估算，计入在途任务。完成后回填服务商用量，区分估算、已报告和未知。面向 MCP 客户端的上下文体积单独观察，客户端实际 Token 以客户端可提供的数据为准。 |
| 服务商上下文缓存 | 应用能复用结果时直接取已有记录。需要调用模型时，把稳定指令与格式放前面，场景差异放后面。按服务商报告的缓存命中、写入和实际计费评估收益。[OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching) · [Gemini Context Caching](https://aistudio.google.com/docs/caching) |

接入首个文本模型前，先用现有在线图像任务打通用量记录，并补齐 WebUI 与 MCP 的按 ID 取用。用同一份多场景样例测首次处理、无改动复跑、改一句台词，以及沿用提示词另出候选。比较外部调用次数、输入与输出 Token、耗时及每个获批产物的费用。费用包含重试和未采用的候选，同时抽查剧情证据、角色别名与跨章关联。

### 后续验收

新增操作同时提供 MCP 入口，WebUI 与 MCP 共用后端和任务记录。以没有模型和历史产物的克隆起步，每阶段保留输入样例与预期输出，供以后复跑。

| 阶段 | 工作 | 完成条件 |

### 待定问题

独立 VS Code 集成、第二个引擎和跨引擎中间表示 G-SIR 按实际需求推进。跨引擎范围由两个引擎的实际脚本样例决定。

| 待定问题 | 先用什么判断 |
| --- | --- |
| 演出上下文如何变成舞台动作 | 写两场发生在同一地点但演出不同的戏，核对背景、立绘和音乐的触发位置。 |
| 人物身份、说话人别名、立绘和 TTS 如何对应 | 用第一人称主角、同一角色的两个称呼，以及只有台词没有立绘的角色做对照。 |
| 演出指令与控制流的可移植范围 | 用出入场、表情切换、音乐变化和分支汇合的脚本样例，对照目标引擎能表达的语义。 |
| 剧本修改后，哪些需求和绑定可以沿用 | 分别试改台词、移动一幕、更换角色衣着、撤回一条配音，比较每次应重新审阅的范围。 |
| 跨引擎如何处理缺失资产与能力差异 | 分别去掉配音、背景和立绘，在候选引擎里实际编译和预览，记录每种缺省情况下可接受的表现。 |
