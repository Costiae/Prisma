# Prisma · 视觉小说制作管线

当前版本提供本地 Web UI 和 Python 命令行。`draft` 把原始文本整理成可校对的 Scenario，`build` 把校对后的剧本和指定的演出、素材写成原生 Ren’Py `.rpy`。可以先生成纯文字工程，再在工作台制作背景、立绘和 CG，或导入已有素材。

## 本地 Web UI

从仓库根目录启动。需要 Python 3.11 或以上版本，仅使用标准库。

```powershell
python webui.py
```

打开 [本地工作台](http://127.0.0.1:8765)。可以载入车站样例、导入 UTF-8 原文，或直接编辑已有的 Scenario。解析后点击一条台词，选择演出动作和已经添加的素材。最后下载 Ren’Py ZIP，解压后在 SDK 中打开。中文预览时可在「添加素材」上传中文字体，再从字体下拉框选中它。

编辑内容保留在当前页面。刷新前可下载 Scenario 和演出 JSON，之后重新导入并选择素材。增删场景或台词后请重新核对演出位置。端口冲突时可加 `--port 8766`。单次构建支持最多 45 MiB 的选中素材，较大的工程可用命令行构建。

## 从零开始与 MCP

没有模型时，可以配置在线图像 API 直接生成，也可以用本地工具箱安装底模、导入自己的参考图并训练 LoRA。WebUI 与 MCP 共用一个服务和任务目录，Scenario、素材提示词、安装、训练、出图、复跑、产物读取和 Ren’Py 导出都可通过 MCP 操作。直接连接 `http://127.0.0.1:8765/mcp`，或为 stdio 客户端配置 `mcp_stdio.py`。[从零开始、MCP 配置与可复跑示例](docs/reproducible-workflow.md)

### 图像工作室

在顶部选择「图像工作室」。可以粘贴提示词、载入近景肖像／双人花园／图书馆样例，或把当前场景的几句文本带入提示词，再补充人物外观、动作和构图。生成后可预览、下载，或点「加入素材」，在「演出与素材」中将它用作背景或立绘。候选图和任务记录会留在磁盘；可以复用以前的生成参数，或将候选图重新加入当前工程。

| 模式 | 使用方法 |
| --- | --- |
| 本地模型 | Windows x64 使用 Vulkan 推理和 CUDA 训练；Apple Silicon Mac 可用 MPS 训练 SD 1.x/SDXL LoRA，也可用 Apple MLX 在 512 分辨率训练 Iris-3B 或动漫专用 Anima Base LoRA，并通过 MLX 本地生成。 |
| 在线模型 | 在启动 `webui.py` 的进程环境中设置 `OPENAI_API_KEY`，再切换到「在线模型」。请求走 OpenAI 图像 API，会发送提示词并使用账户额度。密钥只留在服务端环境中。 |

本地模式会查找 `E:\LLM\prisma-media`（可用 `PRISMA_MEDIA_HOME` 指定已有安装的位置）和本项目以往的 R1/R2/R3 权重。选择「套用 R2 / R3 对照配置」可按相同 Seed 比较 R2、R3 各自 200 步、0.35 权重的结果。两支权重相互独立，可以分别继续使用。

LoRA 工具箱可自动拉取约 2.13 GB 的 Anything V3 或 6.94 GB 的 Animagine XL 4.0 Opt（动漫专用 SDXL checkpoint），以及训练用的 Python 3.10.20、PyTorch、sd-scripts 和对应的 CLIP 分词文件。Windows 使用 CUDA 12.4 与 8-bit AdamW；Apple Silicon 使用 PyTorch 2.8 MPS 与标准 AdamW。Iris-3B 与 Anima 使用独立的 Apple MLX 环境，固定 Python 3.13 和 MFlux 提交 `02b92461ec246ec44f5149b5dc3f69817a263a67`。Iris 下载约 20 GB；Anima Base 下载动漫底模、VAE 和分词器，合计约 5.7 GB。Anima Base 固定到官方仓库提交 `457fbf842cb86e96af72c65bdd13e3f1c448de84`，训练输出为 ComfyUI 兼容 LoRA。Anima 模型与衍生权重仅限非商业用途。训练任务会记录模型提交、权重校验值、依赖版本和数据集清单。首次安装需联网并预留下载和解压空间。工具箱还可以：

1. 从 `Reference/Img`、R2/R3 原训练集或上传的图片选择训练素材，编辑每张图的标注并保存为独立数据集。
2. 选择 SD 1.x、SDXL、Iris-3B Base 或 Anima Base，设置步数、保存间隔、Rank、学习率和 Seed，训练独立分支。Iris 和 Anima 使用 512 分辨率、batch size 1、梯度检查点和 2 GB MLX 缓存；步数会按数据集大小取整为完整轮次。Anima 默认 Rank 16、25 个数据轮次，并使用其全部 28 层的注意力、MLP 与 AdaLN 模块。可查看日志或取消本地任务。训练完成后，可下载预览图与 checkpoint；Apple Silicon 可直接用 MLX 生成 Anima Base 与 LoRA 对照图。
3. 导入兼容 SD 1.x 的 `.safetensors` LoRA。大于 45 MiB 的文件可直接复制到 `build/prisma-images/loras`，再刷新环境。

新下载、数据集、任务日志、出图和训练权重默认写在 `build/prisma-images/`；可通过 `--image-workspace` 自定义位置。工具箱不会改动原参考图或既有 R2/R3 训练结果。

## 运行基础流水线

构建需要 Python 3.11 或以上版本，仅使用标准库。从仓库根目录运行，先把 `path/to/novel.txt` 换成实际文件路径。中文预览可用 `--font` 指定覆盖所需字符的字体，示例使用 Windows 的微软雅黑。

```powershell
python prisma.py draft 'path/to/novel.txt' build/scenario.md
# 先校对 build/scenario.md 中的说话人，再构建。
python prisma.py build build/scenario.md build/novel --font C:/Windows/Fonts/msyh.ttc
```

`draft` 保留原文顺序，识别 `#` 章节标题，并将 `---`、`◇◇◇` 和缩进的数字分节整理成 Scenario 的 `---` 换场标记。整段用 `「」` 包住的文字在未指定说话人时标为 `？：`，须在构建前校对。可以直接编辑生成的 Markdown，也可以用 `--speakers` 提供 JSON，键为原文行号，值为角色名。将值写为 `null` 可把该引号段保留为无署名文本。带卷首简介的小说可以用 `--from-heading '# 章节名'` 指定起点，此时说话人仍按原文行号填写。

`build` 检查说话人并生成 `game/script.rpy`。省略 `--cues` 就生成纯文字版。要挂载已有素材，可按下例创建 `cues.json`，填入实际文件路径，再用 `--cues cues.json` 构建。`1:1` 指第一章第一场，`1` 和 `4` 指该场的第一条和第四条展示文本。在下文的车站 Scenario 中，第四条是周明的第一句对白。每条列表里的动作在对应文本显示前依次执行。相对素材路径以 JSON 文件所在目录为基准，输出工程只复制用到的文件。

```json
{
  "1:1": {
    "1": [{ "background": "assets/station.png" }],
    "4": [
      { "show": { "actor": "周明", "file": "assets/zhouming.png" } },
      { "voice": "assets/zhouming-line-1.wav" }
    ]
  }
}
```

现有动作包括 `background`、`show`、`hide`、`music`、`sound` 和 `voice`。`music: null` 停止音乐，每句有署名的对白最多挂一条 `voice`。换场只推进剧情顺序，画面和音乐延续到相应的演出指令。增删场景或展示文本后，需要重新核对 JSON 中的位置编号。重复运行时请为 `draft` 选用新的输出文件，为 `build` 选用新的输出目录。

预览需要单独安装 Ren’Py SDK。在 Launcher 里将项目目录设为 `build` 的绝对路径，选择生成的 `novel` 工程。Windows 也可从 SDK 目录运行语法检查，将下例的路径替换为实际工程目录。

```powershell
.\lib\py3-windows-x86_64\python.exe renpy.py 'C:\path\to\Prisma\build\novel' lint --error-code
```

目前已用车站样例、Bukiyou 小说片段和《转生了的大圣女》的序章验证 Scenario 和 `.rpy` 生成。Bukiyou 片段也验证了素材挂载。Ren’Py 的 lint 和实际播放仍待验证。

## Scenario 格式

| Scenario 写法 | 含义 |
| --- | --- |
| `# 章节名` | 开始新章。章内有正文时，从第一场开始。 |
| 独占一行的 `---` | 分隔章内场景，前后留空行。 |
| 独占一行的 `$[角色名]` | 标记接下来的叙述视角。它是编辑信息，不触发演出，也不决定对白的角色或配音归属。 |
| `说话人：内容` | 有署名的对白。说话人后可以写括号里的动作或语气，构建时只读取角色名和台词。 |
| 普通正文 | 无署名的展示文本，可写环境描写、第一人称叙述和内心活动。每个非空正文行是一条展示文本，紧接着缩进至少两个空格的行作为同一条的续行。 |
| 行首的 `\` | 将形似对白、章节、换场或视角标记的行按正文显示。 |

```text
# 第一章　末班车

$ 林岚

雨敲着玻璃。

我抬眼，看见周明站在门边，手里捏着一张车票。

林岚（压着火）：你还知道回来。

周明（把车票翻了个面）：末班车还没走。

他还是没回答我的问题。

---

走出车站时，雨已经停了。
```

### 资产分支与审批

各资产分支计划按下表接入。素材进入 Script 的时机由该分支的审批决定。

| Scenario 派生的产物或分支 | 输入与去向 |
| --- | --- |
| 章节梗概 | 从 Scenario 提取，供作者按章审阅。 |
| 内容总览 | 从 Scenario 提取，为背景和音乐提供上下文。音乐分支还可接收音乐参考。 |
| 角色概览 | 与角色参考一起用于确定角色基准立绘，与人声参考一起用于确定角色声音基准。 |
| 立绘差分和 CG | 沿用角色基准立绘。差分可以复用底图，只保存变化的局部，由资产处理和导出负责合成。 |
| 角色语音 | 用 Scenario 的台词和该角色的声音基准生成。 |
| Script | 根据 Scenario 确定演出，接收已批准的音乐、背景、立绘、CG 和角色语音。 |

1. **从剧本提取制作需求。** 人读的摘要按全文、章节、场景组织。供生成使用的摘要按分支挑出所需背景，例如人物外观与性格、场景环境、作品的音乐基调。两种摘要各自服务于不同读者。
2. **先定 Tag，再生成候选。** Tag 描述剧本需要的资产，在构造 Prompt 时确定。表情和音乐分别使用受控词表。角色有基础表情，也可以根据人物摘要扩展自己的表情枚举。Script 使用词表允许的值。
3. **按媒介组织生成输入。** Prompt 由相关文本摘要、同媒介参考和人工补充提示词组成。软件级画风参考可以供项目复用。项目内从角色设计到基准立绘，再到差分和 CG，沿用上游确定的外观。TTS 以角色为单位复用音色母本。参考音乐可先提炼为生成提示。
4. **在创作性环节设闸门。** Scenario、资产 Prompt、候选和挂载结果都要有审阅机会。默认等待人工决定，可显式放行。打回退到当前闸门的直接上游。候选未获批准时留在候选池，批准后才能作为该需求的可用资产。
5. **允许部分挂载和增量更新。** 背景通过就能先挂背景，角色语音可以晚些通过，也可以省略。后续补配音时应保留已通过的背景。若已挂载资产被打回，原型要能验证对应绑定的撤回。上游修改波及哪些批准记录，需用实际编辑样例明确。

### 后续验收

每阶段保留输入样例和预期输出，供以后复跑。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| Ren’Py 预览 | 用 SDK 检查现有的纯文字版和带演出版。 | 两版都能通过 lint 并实际播放。加入配音后，原背景引用保持一致。 |
| 演出化与审批 | 增加演出建议、剧情选项与跳转，再用准备好的背景和语音候选验证审批。 | 选项能跳到指定场景。背景候选打回后可以重新提交，批准背景后可先预览，配音可稍后挂载。 |
| 多场景编辑与资源管理 | 统一 UI 支持审剧本、看候选、校对挂载、管理资源与预算。处理剧本局部修改和资产撤回。 | 改一场戏或打回一项资产时，能定位受影响的需求和绑定。 |
| 接入生成模型 | 先选一条素材分支验证 Prompt、参考和筛选，再扩展到其他媒介。 | 模型产物进入同一套审阅和挂载流程。单条分支生成失败后可重新执行。 |
| 增加引擎与入口 | 按需增加第二个引擎，并接入 VS Code 与 Agent/Skill。 | 可移植的 `.rpy` 内容能导出到第二个引擎。不同入口看到一致的项目状态和审批结果。 |

### 待定问题

等需要导出到另一个引擎时，从 `.rpy` 解析可移植的语句，再转成目标引擎能用的中间表示。G-SIR 的字段和可移植范围由两个引擎的实际脚本样例决定。

| 待定问题 | 先用什么判断 |
| --- | --- |
| 演出上下文如何变成舞台动作 | 写两场发生在同一地点但演出不同的戏，核对背景、立绘和音乐的触发位置。 |
| 人物身份、说话人别名、立绘和 TTS 如何对应 | 用第一人称主角、同一角色的两个称呼，以及只有台词没有立绘的角色做对照。 |
| 演出指令与控制流的可移植范围 | 用出入场、表情切换、音乐变化和分支汇合的脚本样例，对照目标引擎能表达的语义。 |
| 剧本修改后，哪些需求和绑定可以沿用 | 分别试改台词、移动一幕、更换角色衣着、撤回一条配音，比较每次应重新审阅的范围。 |
| 跨引擎如何处理缺失资产与能力差异 | 分别去掉配音、背景和立绘，在候选引擎里实际编译和预览，记录每种缺省情况下可接受的表现。 |
| 生成预算、插件和多入口写入的细则 | 在单场景跑通后，结合真实模型成本、第二个引擎差异，以及两个入口同时操作同一项审批的例子再定。 |
